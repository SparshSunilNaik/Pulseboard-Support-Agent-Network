Every support question takes a route you can trace.

A LangGraph agent for Pulseboard, a made-up analytics product. It sorts each question, answers the ones it can back up with the help docs, and hands the rest to a person. All three models run on your own machine.

    Six stops, two kinds of work

    The graph keeps judgment and bookkeeping apart. Only two stops ask a model anything. The rest is plain code you can test without loading a single weight.

    1. Triage

      Rules, then embeddings

      Puts the question into one of four classes: answerable, needs clarification, needs escalation, or out of scope. Keyword rules catch the obvious cases like refunds. Otherwise it compares the question to example sentences for each class. If nothing is close enough, it asks for clarification instead of guessing.

      support_agent/triage.py

    2. Retrieval

      Plain code

      Finds the six help-article sections and past tickets closest to the question by cosine similarity, then a small cross-encoder reorders them.

      support_agent/retrieval.py

    3. Generate

      Language model

      Qwen2.5 0.5B writes an answer from the retrieved passages only. Sources are attached by code, not by the model, so it can’t cite a document it never saw.

      support_agent/generation.py

    4. Verify

      Plain code

      Checks the draft: every cited source was retrieved, the answer shares real vocabulary with the evidence, it isn’t a stub, and it doesn’t promise things like refunds. A failed draft goes back to Generate once. A second failure stops the run.

      support_agent/verification.py

    5. Finalize

      Plain code

      Builds the output JSON: answer, sources, a confidence score from retrieval similarity, and the trace of every node that ran.

      support_agent/graph.py

    6. Safe response

      Plain code

      Template replies for everything the agent shouldn’t answer alone. It asks for the missing detail, lists what to collect before escalating, or points billing requests to billing. Each one is flagged for a person.

      support_agent/safe_responses.py

    No API keys, no network after the first download

    Three Hugging Face models, each pinned to an exact commit. Once they’re cached, set HF_HUB_OFFLINE=1 and the agent runs with the network unplugged.

    Where it falls short

    The writer is small. A 0.5B model keeps the agent fast on a CPU, but its answers can be wordy, hedge, or pick up claims from a passage it misread.

    Verify checks words, not meaning. It measures overlap with the evidence and confirms citations exist. It doesn’t run a second model to check that each claim is actually true.

    No memory between questions. Every run starts fresh, so a follow-up like “did that work?” has nothing to refer back to.

    Run it yourself

    Python 3.11 or newer. The first run downloads about 1.2 GB of model weights.

    1. Get the code and install

      git clone https://github.com/SparshSunilNaik/Pulseboard-Support-Agent-Network.git
cd Pulseboard-Support-Agent-Network
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

      On macOS or Linux, activate with source .venv/bin/activate.

    2. Ask a question

      python -m support_agent.cli "Can a read-only user create API credentials?" --verbose

    3. Run the tests

      python -m pytest tests/ -v

      The routing tests use stub models and finish in seconds. The end-to-end tests load the real ones.
